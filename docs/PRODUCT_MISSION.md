# 產品使命與證據基線

狀態：`2026-08-11 / pre-alpha / Mission Gate: AMBER（本 iteration 前為 RED）`

## 結論先行

repository 原本是視覺完成度高、但會誤導出發決策的 prototype；本 iteration 已收斂成可追溯的臺南正常週期查證工具。它仍不是 public beta：下一步要證明陌生使用者能快速選到適合候選，並完成真實使用者與四週維護驗證。

> 在 15 秒內，讓手機使用者找到一個在臺南、所選日期**依可驗證正常週期營業**的夜市；所有會影響出發的欄位都有來源、核對時間與未知狀態，並可一鍵交給地圖確認位置或分享。

第一個 beachhead 是「臺南市政府列冊、具有正常週期營業資料的夜市」。這不是宣稱即時營業；臨時停業、天候、節慶與現場異動若沒有可靠訊號，產品必須明說不知道。

## 為何推翻原本的產品形態

### 1. 核心承諾目前會造成白跑

- `2026-08-09` 是星期日，但首頁預設沒有套用今日營業日，仍顯示 19 個夜市；其中包含 repository 自己標記星期日不營業的旱溪、武聖與大東。
- 首頁文案承諾「挑今晚適合的夜市」，卡片卻只顯示時鐘區間、不顯示營業星期，讓使用者無法辨識以上錯誤。
- 武聖夜市被標成「官方資料」且只列週三、週六；[臺南市政府 live dataset](https://soa.tainan.gov.tw/Api/Service/Get/611e74b4-d09a-4712-b421-aa062fd02854) 的對應紀錄是「每週三五六」。

### 2. 「官方」被錯誤放大成整筆背書

[臺南市列冊資料](https://data.gov.tw/dataset/53634)只提供名稱、許可路段或區域、正常營業日等窄欄位，並不支持目前卡片上的精確鐘點、美食、交通、步行時間、座標或推薦路線。一個 market-level 的「官方資料」標章，會使使用者誤以為所有欄位都經官方確認。

### 3. 漂亮、今日篩選與地圖不是差異化

現有產品已提供更廣的收錄與今日篩選，例如 [今夜有市](https://tonightmarkets.com/)、[WeKenGo 夜市清單](https://wekengo.tw/night-markets/) 與地圖型夜市產品。Google Maps 也是「附近＋導航」的強替代品。可守住的差異不是資料量，而是：

- 決策欄位逐欄位附來源；
- 來源衝突不靜默覆蓋；
- 核對時間與 stale 狀態可見；
- 不確定時不做正向推薦；
- 使用者可在選定後直接導航，而不是閱讀一段策展文案。

## 真實需求的證據

- 交通部觀光署的 [2024 來臺旅客調查](https://admin.taiwan.net.tw/businessinfo/IssuePage?a=14693) 顯示，夜市是 85.06% 受訪來臺旅客參與的活動；需求本身成立。
- [2024 臺灣旅遊狀況調查](https://admin.taiwan.net.tw/businessinfo/IssuePage?P=1&a=14644) 顯示國旅以個別安排與短程決策為主；產品應優先縮短「今晚去哪、如何到」的決策時間。
- 官方資料現況是分散且欄位不一致：臺南有正常營業日、[臺中列管夜市](https://data.gov.tw/dataset/85028)有營業頻率、觀光署 [景點資料](https://data.gov.tw/dataset/7777)多數夜市缺營業時間。中央彙整資料不能被當成完整且即時的全國真相。

## 第一階段的使用者與工作

主要使用者：已在臺南或即將前往臺南、用手機在當天下午至晚上決定行程的一般使用者。

核心工作：

1. 打開就看到「今天日期」與依正常週期有營業的結果。
2. 在 15 秒內理解這不是即時開門保證。
3. 看見夜市名稱、正常營業日、許可區域、資料狀態與最後核對時間。
4. 一鍵交給地圖導航，或分享含日期與夜市的可重現連結。
5. 當資料過期、衝突或未知時，理解風險而不是被綠色成功狀態誤導。
6. 若已知目標行政區，可用官方代碼縮小候選；這不是附近、距離或推薦。

## 目前可逆的相關性假設

夜市名冊的 32 筆資料分散於 19 個官方行政區，且每個星期的候選跨 4–8 區。現有搜尋原本只比對名稱與許可路段，無法可靠處理「我想找東區／安南區」這種需求。行政區 control 因此是可逆實驗：只把既有候選以 `adminCode` exact match 縮小，不產生新候選、排序、距離、定位或 live claim。

行政區名稱需同時有兩段官方 lineage：夜市名冊中的 `adminCode`，以及臺南市政府[各區代碼](https://data.tainan.gov.tw/DataSet/Detail/70d961d2-9f38-4112-847d-907b436820ab)的 code-to-name reference。缺任一段就 fail closed。

它只有在 paired 5-user mobile test 滿足以下條件時才保留：至少 4/5 在 30 秒內選對日期與已知行政區候選並啟動 Maps、0 人誤認為附近／距離／即時營業、完成者中位時間相較 baseline 改善至少 25%。任一不成立即移除 select，最多保留有來源的區名顯示；Mission Gate 不會因功能完成升級。

## 必須保留與必須退出公共首頁的內容

保留：

- 現有 Travel 視覺語言與中／英文切換；
- 靜態、低成本、無 credential 即可部署的架構；
- 搜尋、星期篩選、深連結與 responsive detail 的基礎；
- 來源概念，但改為 field-level evidence。

退出公共首頁：

- 兩個視覺版本並排比較；
- 整張卡片的「官方資料」標章；
- 把美食標籤、氣氛分數、固定 90 分鐘路線當成可信決策依據；
- 以 disclaimer 掩蓋資料錯誤；
- 沒有來源的精確鐘點、步行時間與推薦結論。

原型資產可保留在非公開 lab route，不刪除既有內容。

## 成功指標與 release gate

第一階段必須同時滿足：

- ≥ 80% 首次使用者能在手機上於 30 秒內選到指定日期正確候選並啟動導航；
- ≥ 90% 測試者能分辨「官方正常週期」「本產品資料比對」「過期／未知」；
- 100% 關鍵欄位具有 source URL、record ID、retrievedAt、sourceUpdatedAt（若來源未提供則明示 unknown）與 verifiedAt；
- 已知錯誤不得顯示為 confirmed，抽查準確率目標 ≥ 99.5%；
- stale 資料會自動降級，不能進入正向「今晚推薦」；
- 官方名冊 32 筆的 pilot 維護成本 ≤ 2 小時／週；回報 72 小時內分流、7 日內關閉或標示未決；
- 至少完成兩輪真實任務 mobile usability test，才可稱 public beta。

產品可上線後的 outcome 指標：導航或分享轉換率 ≥ 20%，28 日回訪率 ≥ 15%。若 500 次合格使用後導航／分享低於 20% 且回訪低於 10%，應停止擴張並評估改為嵌入式資料服務，而不是繼續做全台 coverage。

## 明確 anti-goals

- 不追求最快收錄全臺或以筆數競賽；
- 不宣稱即時營業，除非日後有可稽核的例外事件來源；
- 不抓取或長期快取 Google Places 內容來填補資料；
- 不以行政區 select 偽裝 GPS、附近、距離或推薦；
- 不以無來源的美食排名、AI 行程或氣氛分數建立核心價值；
- 不在第一階段加入帳號、社群、廣告或付費功能；
- 在維護 SLO 未證明前，不擴張到第二個縣市。

## 仍需用實驗回答，而非憑直覺決定

- 「列冊夜市」是否符合一般使用者心中的夜市範圍；
- 使用者是否真的會因逐欄位來源與不確定性而改變選擇或願意分享；
- 官方資料衝突時，哪種呈現能幫助決策而不造成認知負擔；
- 一位維護者能否持續達到 freshness 與回報 SLA。
