# 介面設計研究：地點查找類產品怎麼呈現「今晚能去哪裡」

研究日期：2026-10-22。目的：在不違反[資料信任契約](DATA_TRUST_CONTRACT.md)的前提下，重做 public product 的首頁與詳情頁。使用者與裝置分析見 [ux-research.md](ux-research.md)。

> 驗證程度：Google Maps「Open now」篩選、OsmAnd POI 篩選、開源 store locator 的「Open now」邏輯、MapLibre 定位、臺灣裝置比例（StatCounter）是本次以網路搜尋核對過的；其餘條目依產品公開介面的一般觀察整理，未逐一截圖存證，細節可能隨版本變動。

## 一、同類產品：拿來做什麼、哪裡值得借鏡

| 產品 | 使用者拿它做什麼 | 技術／地圖 | 卡片與篩選 | 行動版 | 營業時間呈現 | 資料來源呈現 | 值得借鏡 |
|---|---|---|---|---|---|---|---|
| Google Maps 清單 | 「附近有什麼、現在開不開」 | 自家向量地圖 | 頂部橫向 chip（營業中、評分、價位）；卡片：名稱、評分、類別、「營業中・22:00 打烊」 | 地圖在上、可拖曳 bottom sheet 列表 | 綠／紅狀態 + 下一個變化時間；「營業中」篩選預設不開，被批評常列出已打烊店家 | 幾乎不揭露 | 狀態放在卡片第二層；chip 篩選 |
| Yelp | 依評價挑餐廳 | Mapbox 類瓦片 | 篩選 chip 列（Open Now、價位、距離）；大圖 + 星等 | 列表為主，「Map」浮動按鈕切換 | 卡片內「Open until 10 PM」 | 商家自報 + 社群編修，不標更新時間 | 列表／地圖切換鈕 |

| 愛食記 | 看部落客食記找餐廳 | Google Maps | 依城市、類別、排行榜瀏覽；照片為主 | App 有「附近食記」定位鍵 | 詳情頁列出營業時間 | 引用部落客文章 | 在地化中文用語 |

| OsmAnd（開源，GPL-3.0） | 離線地圖與 POI 搜尋 | OpenStreetMap 向量 | 「Open now／24/7」等多種過濾器 | 原生 App | 依 OSM `opening_hours` 計算 | 可回溯到 OSM 編修紀錄 | 資料可追溯的精神 |
| 開源／商用 store locator（MapLibre GL JS〔BSD-3〕、Leaflet〔BSD-2〕、WordPress 外掛） | 品牌門市查找 | MapLibre / Leaflet + OSM | 左側清單 + 右側地圖、區域下拉、分類 checkbox | 清單與地圖上下堆疊或分頁 | 卡片顯示營業時間並計算「Open now」 | 多半不揭露 | 桌機清單＋地圖並排的版型 |

### 開源參考與授權

本次**沒有複製任何外部程式碼**，只參考了互動模式：

- 分段切換、chip 群組沿用 [Radix UI](https://www.radix-ui.com/)（MIT）Toggle Group 的語意：`role="group"` + `aria-pressed`，以原生 `<button>` 自行實作，不引入套件。
- 行政區方格圖（tile grid map）的概念來自新聞資料視覺化常見的 tile cartogram（例如美國各州方格圖）；格子位置是依臺南官方 37 區自行排列（`src/product/districtTiles.ts`），並有測試確保 37 區各出現一次、不重疊。
- 若日後改用真地圖，MapLibre GL JS（BSD-3-Clause）與 Leaflet（BSD-2-Clause）都與本 repo 的 MIT 授權相容；OSM 資料需標示 ODbL 出處。

## 二、觀察

1. **「現在能不能去」永遠是第一層資訊。** 但對照組都假設有精確鐘點；官方名冊只有正常營業日，所以只能回答「所選日期依週期是否排班」。
2. **列表與地圖要能並排或切換，切換不遺失條件。**
3. **篩選以 chip 呈現、狀態寫進 URL。** 本專案已用 `?date=&q=&district=` 保存狀態。
4. **日期是夜市特有的主軸。** Tabelog 的「定休日」比「營業中」更接近；七天日期列直接標出每天候選數。
5. **來源揭露是差異化。** 每張卡一行「來源・比對日期」，細節留給詳情頁。
6. **地圖不能捏造座標。** 名冊沒有經緯度；用名稱 geocode 會產生看起來精確、實際不可追溯的點。

## 三、主流前端設計語言

| 參考 | 我們學到的 | 落實在哪裡 |
|---|---|---|
| Linear | 中性底色 + 單一強調色、細邊框、緊湊字距、鍵盤焦點清楚 | `edge` 細邊框、`lantern` 為唯一強調色、`tracking-tight` 標題、全站一致 `focusRing` |
| Vercel (Geist) | 以 token 驅動的深淺色、黑白高對比主按鈕 | 主按鈕 `bg-fg text-canvas`（淺色為黑底、深色為白底）；所有顏色經由 CSS 變數切換 |
| Stripe | 有層次的陰影與漸層建立「主視覺 → 操作面板」的前後景 | Hero 下方浮起的篩選面板（`-mt-8` + `shadow-xl`） |
| Airbnb | 篩選 chip、卡片資訊層級（徽章 → 標題 → 次要資訊） | 卡片：狀態徽章 → 名稱 → 七日排班點 → 許可區域 → 來源列 |
| Google Maps | 手機上列表／地圖切換、狀態色語意 | 手機分段切換鈕；綠＝排定、琥珀＝需確認、灰＝無法判斷 |
| Observable | 資料敘事：先給結論數字，再給可檢查的細節 | Hero 大數字；七日排班點陣（小型 sparkline 式資料圖形） |
| Radix / shadcn/ui | 無障礙優先的元件語意、以 CSS 變數命名的語意 token（`background`、`foreground`、`muted`、`border`） | `tailwind.config.ts` 的 `canvas/surface/raised/fg/muted/subtle/edge/lantern/ok/warn/bad/idle` |
| Tailwind | utility-first、以設定檔集中 token | 所有新樣式都用 token utility，沒有寫死顏色（hero 文字除外，因為它永遠疊在深色照片上） |
| Design tokens | 一組語意命名對應淺／深兩組值 | `src/index.css` `:root` 與 `:root.dark` 兩組 RGB 值；`index.html` 在首次繪製前套用主題，避免閃爍 |

**本專案的設計語言**：「燈籠夜色」——暖紙色底（淺色）／墨藍夜色（深色），燈籠紅為唯一強調色，琥珀用於數字與警示；系統 CJK 無襯線字型（PingFang TC／Noto Sans CJK／微軟正黑體），以字重而非字型變化建立層級；圓角 12–24px、1px 細邊框、只有主視覺與浮起面板使用陰影。

## 四、採用什麼、為什麼

| 決定 | 採用 | 理由 |
|---|---|---|
| 框架 | 維持 React 18 + Vite + Tailwind，不新增依賴 | 既有測試、CI、Pages 部署都建立在這套上 |
| 主力裝置 | 手機 390px 優先，桌機 1440px 雙欄 | 臺灣網頁瀏覽手機占 58%，本產品晚間即時決策情境更偏行動（見 ux-research） |
| 地圖 | **不用 MapLibre／Leaflet，改用臺南 37 區示意方格圖** | 名冊只有行政區代碼。方格圖每格就是一個官方行政區，顏色代表所選日期候選數，點選即套用篩選；零外部瓦片請求，並標示「非比例地圖，也不代表夜市位置」 |
| 首頁第一眼 | 大數字「N 個夜市依週期排定營業」+ 七日日期列（每天附候選數） | 學 Google Maps 把狀態放第一層、學 Observable 先給結論 |
| 篩選 | 狀態 chip + 行政區下拉 + 搜尋；日期、行政區、搜尋寫進 URL | 學 Yelp／Airbnb 的 chip；保留可分享 URL |
| 卡片 | 狀態徽章、名稱、行政區、七日排班點、許可區域、來源與比對日期 | 營業日點陣比文字更快掃讀；來源每筆可見但只占一行 |
| 詳情頁 | 判斷卡在上（狀態、排班點、導航／分享），逐欄位 evidence 在旁／下 | 決策先、證據後；evidence 資料模型不變 |
| 深淺色 | 預設跟隨系統，可手動切換並記住 | 夜市在晚上查 |
| 字型 | **不載入網頁字型**，使用系統 CJK 字型 | 初版用 Google Fonts 的 Noto Sans/Serif TC，Lighthouse 行動版 Performance 只有 55（237 KB 阻塞 CSS、FCP 15.6 s）；改系統字型後為 99 |
| Hero 圖 | 2.4 MB PNG → 156 KB（桌機）／50 KB（手機）WebP，依寬度 preload；標註「示意插圖」 | 原圖是生成插圖，不能讓人誤以為是某個真實夜市 |

## 五、刻意不做

- 不顯示「營業中／已打烊」或精確鐘點：名冊沒有這些欄位。
- 不做「附近」或距離排序：沒有座標，也不要求定位權限。
- 不加評分、照片牆或推薦排序：沒有可追溯來源。

## 六、自我審查（2026-10-22，本機 production build）

| 項目 | 結果 | 方法 |
|---|---|---|
| 5 秒看懂 | 首屏依序是日期 → 大數字 → 「不是即時開門保證」→ 名冊比對日期；手機第一屏可看到第一張卡片頂端 | 390×844 截圖人工檢查 |
| 視覺層級 | 每屏只有一個主要強調（hero 數字或主按鈕）；狀態色只用在徽章、排班點與提示框 | 截圖檢查 |
| WCAG AA 對比 | 淺／深色、首頁／詳情／空結果 × 390／1440，axe 0 個 moderate 以上問題 | `@axe-core/playwright` |
| 觸控目標 ≥ 44px | 上述 12 種組合中，所有可見的 `a/button/input/select` 皆 ≥ 44×44 | Playwright 量測 bounding box |
| 版面跳動 | CLS 0（首頁與詳情、手機與桌機） | Lighthouse 12.8.2 |
| 載入狀態 | `LoadingShell` 骨架畫面（已改用 token，深淺色皆適用） | 程式碼審查；未截圖 |
