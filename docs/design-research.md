# 介面設計研究：地點查找類產品怎麼呈現「今晚能去哪裡」

研究日期：2026-10-22。目的：在不違反[資料信任契約](DATA_TRUST_CONTRACT.md)的前提下，重做 public product 的首頁與詳情頁。

> 驗證程度：Google Maps「Open now」篩選、OsmAnd POI 篩選、開源 store locator 的「Open now」邏輯與 MapLibre 定位，是本次以網路搜尋核對過的；其餘條目依產品公開介面的一般觀察整理，未逐一截圖存證，細節可能隨版本變動。

## 比較表

| 產品 | 技術／地圖 | 卡片與篩選 | 行動版 | 營業時間呈現 | 資料來源呈現 |
|---|---|---|---|---|---|
| Google Maps 清單 | 自家向量地圖 | 頂部橫向 chip（營業中、評分、價位）；卡片：名稱、評分、類別、「營業中・22:00 打烊」 | 地圖在上、可拖曳 bottom sheet 列表 | 綠／紅文字狀態 + 下一個變化時間；「營業中」篩選預設不開，被批評常列出已打烊店家 | 幾乎不揭露；「可能有誤」需使用者回報 |
| Yelp | Mapbox 類瓦片 | 篩選 chip 列（Open Now、價位、距離）；卡片以大圖 + 星等為主 | 列表為主，「Map」浮動按鈕切換 | 卡片內「Open until 10 PM」 | 商家自報 + 社群編修，不標更新時間 |
| Tabelog | Google Maps 嵌入 | 左欄密集條件篩選；卡片資訊密度高（評分、預算、定休日） | 列表／地圖分頁 | 詳情頁有完整營業時間表與「定休日」，並註明「營業時間可能變更，請事先確認」 | 標示資訊最後更新日 |
| 愛食記 | Google Maps | 依城市、類別、排行榜瀏覽；卡片以照片與部落客食記為主 | App 有「附近食記」定位鍵 | 詳情頁列出營業時間 | 引用部落客文章，來源是人而非機關 |
| Time Out 城市指南 | 靜態圖 + 偶爾嵌入地圖 | 編輯式長文清單，大圖 + 短評 | 單欄長捲動 | 通常只寫在文字內 | 署名作者與發佈日期 |
| OsmAnd（開源） | OpenStreetMap 向量 | POI 搜尋有「Open now／24/7」等多種過濾器 | 原生 App | 依 OSM `opening_hours` 標籤計算 | OSM 資料、可回溯到編修紀錄 |
| 開源／商用 store locator（MapLibre、Leaflet、WordPress 外掛） | MapLibre GL / Leaflet + OSM | 左側清單 + 右側地圖、區域下拉、分類 checkbox | 清單與地圖上下堆疊或分頁 | 卡片顯示營業時間與公休日，並以時間計算「Open now」 | 多半不揭露 |

## 觀察

1. **「現在能不能去」永遠是第一層資訊。** Google Maps 和 Yelp 都把營業狀態放在卡片名稱下一行，並提供一鍵篩選。但它們都假設有精確鐘點與即時狀態；本專案的官方名冊只有「正常營業日」，所以只能回答「所選日期依週期是否排班」，不能借用「營業中」措辭。
2. **列表與地圖要能並排或切換。** 桌面普遍是「清單＋地圖」雙欄；手機則用 bottom sheet 或「地圖／清單」切換鈕。關鍵是切換不會遺失篩選條件。
3. **篩選以 chip 呈現、狀態寫進 URL。** 可分享、可回上一頁。本專案已用 `?date=&q=&district=` 保存狀態，這點要保留。
4. **日期是夜市特有的主軸。** 一般餐廳查找器只看「現在」；夜市是週期性排班，Tabelog 的「定休日」概念比「營業中」更接近。把一週七天做成橫向日期列、每天直接顯示候選數，使用者能一眼看出「週六最多、週一最少」。
5. **來源揭露是差異化，不是負擔。** 對照組幾乎都不標資料來源與更新時間；Tabelog 的「最後更新日」與「請事先確認」是少數例外。本專案逐欄位 evidence 是核心價值，但首頁不該被說明文字淹沒——每張卡只需一行「來源・比對日期」，細節留給詳情頁。
6. **地圖不能捏造座標。** 名冊沒有經緯度；用名稱 geocode 會產生看起來精確、實際不可追溯的點。開源 store locator 的 pin 地圖在這裡不適用。

## 採用什麼、為什麼

| 決定 | 採用 | 理由 |
|---|---|---|
| 框架 | 維持 React 18 + Vite + Tailwind，不新增依賴 | 既有測試、CI、Pages 部署都建立在這套上；重設計是視覺與資訊架構問題，不是技術棧問題 |
| 地圖 | **不用 MapLibre／Leaflet，改用臺南 37 區的示意方格圖（tile cartogram，純 SVG/CSS）** | 官方名冊只有行政區代碼，沒有座標。方格圖每格就是一個官方行政區，顏色代表所選日期的候選數，點一下即套用行政區篩選。它誠實（不假裝精確位置）、零外部瓦片請求、離線可用，並明確標示「示意位置，非比例地圖」。真正導航仍交給詳情頁的 Google Maps 名稱搜尋 |
| 首頁第一眼 | 大數字「N 個夜市依週期排定營業」+ 七日日期列（每天附候選數） | 學 Google Maps 把狀態放第一層，但用名冊實際能支持的措辭 |
| 篩選 | 狀態 chip（全部／依週期有營業／需再確認）+ 行政區下拉 + 搜尋，日期、行政區、搜尋都寫進 URL | 學 Yelp／Google 的 chip；保留既有可分享 URL |
| 列表／地圖 | 桌面雙欄並排（地圖 sticky）；手機用分段切換鈕 | 對照組的共同做法，切換時條件不變 |
| 卡片 | 狀態徽章、名稱、行政區、七格「週一～週日」排班點、許可區域（折行截斷）、一行「臺南市政府經發局・比對日期」 | 營業日用視覺化點陣比文字更快掃讀；來源與更新時間每筆可見，但只占一行 |
| 詳情頁 | 判斷卡（大狀態 + 七日點陣 + 導航／分享）在上，逐欄位 evidence 時間軸在下 | 決策先、證據後；evidence 內容完全沿用既有資料模型 |
| 深淺色 | 預設跟隨系統，可手動切換並記住 | 夜市在晚上查，深色模式是實際使用情境 |
| 視覺語言 | 燈籠紅／琥珀暖色 + 墨藍夜色，標題用 Noto Serif TC | 呼應夜市燈籠，同時讓狀態色（綠＝排定、琥珀＝需確認、灰＝無法判斷）保持高對比 |
| Hero 圖 | 2.4 MB PNG 轉為約 150 KB WebP，僅作裝飾並標註「示意插圖」 | 原圖是生成插圖，不能讓人誤以為是某個真實夜市 |

## 刻意不做

- 不顯示「營業中／已打烊」或精確鐘點：名冊沒有這些欄位。
- 不做「附近」或距離排序：沒有座標。
- 不加評分、照片牆或推薦排序：沒有可追溯來源。
