# 使用者研究：誰會用「今晚哪裡有市」

研究日期：2026-10-22。方法是桌上研究（desk research）加需求推導，沒有做真人訪談；persona 是依產品範圍、資料限制與公開統計推出的假設，上線後應以實際流量與回報修正。

## Personas

| # | Persona | 情境 | 最在意 | 主要裝置 |
|---|---|---|---|---|
| P1 | **臺南在地居民**（30 歲上班族，住東區） | 下班後決定「今晚吃哪個夜市」；只想知道離家近的那幾個今天有沒有排 | 速度、行政區篩選、今天 vs. 明天 | 手機，通勤或下班路上 |
| P2 | **國內旅客**（台北來的週末旅人） | 旅程前一晚或當天在旅館查：這兩天臺南有哪些夜市排定、要怎麼過去 | 日期切換、一週排班總覽、導航連結 | 手機為主；行前規劃時偶爾用筆電 |
| P3 | **外國背包客**（英語使用者） | 在臺南只待 1–2 晚，不懂「週三、六」這種營業日寫法 | 英文介面、清楚的「這不是即時營業」說明 | 手機，常在戶外、網路不穩 |
| P4 | **資料／公民科技使用者**（記者、開放資料社群、潛在貢獻者） | 想確認資料從哪來、哪裡有衝突、能不能回報錯誤 | 逐欄位來源、更新時間、原始連結、回報管道 | 桌機 |

## 使用情境

1. **晚上 6 點的即時決定**（P1、P3）：打開首頁 → 看到今晚有幾個夜市排定 → 用行政區縮小範圍 → 點一個看導航。必須在 5 秒內看懂第一屏。
2. **行前一週規劃**（P2）：在日期列左右切換，比較哪天選擇最多，再把詳情頁連結分享給同行者。
3. **出發前再確認**（全部）：在詳情頁看到「資料來源對這一天有分歧」或「資料已超過比對期限」時，知道要先查原始來源。
4. **查核與回報**（P4）：從卡片上的「來源・比對日期」進到詳情頁的逐欄位證據，再開原始資料集或回報 issue。

## 前 3 項任務

| 優先 | 任務 | 成功標準 | 介面對應 |
|---|---|---|---|
| 1 | 找出**今晚**依週期排定的夜市 | 首屏不用捲動就能看到數字；手機第一屏就碰得到第一張卡片 | Hero 大數字、日期列預設今天、卡片狀態徽章 |
| 2 | 縮小到**我附近的行政區**或指定夜市 | 1 次點選或輸入即可縮小，條件保留在 URL | 行政區下拉、行政區示意圖點選、搜尋框 |
| 3 | 確認**可信度並出發** | 2 次點擊內看到來源與導航 | 卡片「查看依據與導航」→ 詳情頁 Maps 按鈕與 evidence |

## 非功能需求

| 類別 | 需求 | 目前做法與量測 |
|---|---|---|
| 效能 | 行動 3G/4G 下首屏快速；Lighthouse Performance ≥ 90 | 不載入網頁字型、hero 依螢幕寬度預載 50 KB／156 KB WebP；Lighthouse mobile 99、desktop 100 |
| 可近用性 | WCAG 2.1 AA 對比、鍵盤可操作、觸控目標 ≥ 44px | axe 淺／深色皆 0 個 moderate 以上問題；自動量測所有可互動元素 ≥ 44×44 |
| 可信度 | 永遠不把正常週期說成即時營業；每筆顯示來源與更新時間 | 沿用既有 claim policy；卡片一行來源、詳情頁逐欄位 evidence |
| 韌性 | 資料缺漏、過期、衝突、錯誤連結都有明確狀態 | 過期提示、衝突徽章、無結果空狀態、找不到夜市頁、錯誤邊界 |
| 雙語 | 中英切換即時生效並記住 | localStorage 保存；被封鎖時仍可用 |
| 夜間使用 | 深色模式 | 跟隨系統，可手動切換並記住 |
| 可分享 | 篩選狀態可透過網址分享 | `?date=&q=&district=` |
| 隱私 | 不追蹤、不要求定位 | 無 analytics、無定位權限 |

## 裝置評估：手機是主力嗎？

**假設**：找夜市多半在手機上。

**證據**

- StatCounter（2025-09 至 2026-09，臺灣全網頁瀏覽）：**手機 58.1%、桌機 38.6%、平板 3.4%**。這是全站平均，包含大量上班時間的桌機流量。
- 本產品的任務是「今晚／出發前」的即時決定，情境集中在傍晚與戶外（使用情境 1、3），比全站平均更偏行動。地點與餐飲查詢類服務的行動流量占比一般高於全站平均，但這點我沒有找到臺灣夜市查詢的直接統計，屬推論。
- 數位發展部《114 年數位近用調查》：12 歲以上個人上網率 90.3%，查詢商品或服務資訊的使用率 69.6%，代表目標族群普遍具備行動上網能力。

**結論**：推估本產品手機流量約 **70–80%**（全站 58% 為下限，加上晚間、出門情境上修；未經實測）。因此**手機（390px 寬）是主力設計對象**：首屏必須在手機上回答「今晚幾個」並碰到第一張卡片；桌機（1440px）作為規劃與查核用途，提供列表＋示意圖並排與完整證據欄。上線後若加入隱私友善的流量統計，應以實際比例修正。
